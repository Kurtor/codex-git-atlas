# Git Atlas v1.5.0 分支行为验收

验收范围：1440 × 1024 Windows 桌面窗口，合成真实 Git 历史包含一次 Rebase 和一次非快进 Merge，同时使用 Git Atlas 自身仓库回归既有功能。

## 设计结论

分支行为采用“拓扑锚点 + 行内徽标 + 详情证据”三层表达。Merge 使用菱形节点表示多线汇合，Rebase 使用双环节点表示历史重写；颜色只作为辅助，形状和文字保证不依赖颜色也能区分。

## 识别边界

- Merge 依据提交的多个父级识别，是仓库历史中的稳定事实。
- Rebase 依据本机 HEAD reflog 的开始与完成记录配对，能还原变基分支和目标基线。
- Rebase 信息不会写入 Git 提交对象，reflog 过期或关闭时不显示，界面不会通过提交时间或拓扑形状猜测。

## 视觉证据

- Merge：琥珀色菱形节点、合并徽标、详情区来源与目标分支、父线数量。
- Rebase：紫色双环节点、`REBASE` 徽标、详情区来源与目标分支、reflog 证据说明。
- 提交演化：顶部增加分支行为总数，信息带分别统计合并事件和 Rebase 事件。
- 范围档案：质量信号区持续显示当前筛选范围内的两类事件数量。

## 验证结果

- 解析单元测试：Merge 提交标题、Pull Request 标题、Rebase 开始和完成配对全部通过。
- 合成真实仓库：检测到 1 个 Merge 和 1 个 Rebase，3 项分支行为界面断言全部通过，渲染器错误为 0。
- Git Atlas 自身仓库：原 18 项桌面检查与新增 3 项分支行为检查共 21/21 通过，渲染器错误为 0。
- TypeScript、Vite 生产构建与 Windows 便携版封装均通过。
- Windows 便携版空闲采样：5 个进程，工作集约 377.5 MB，私有内存约 245.4 MB，5 秒整机 CPU 采样为 0%。
