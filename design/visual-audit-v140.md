# Git Atlas v1.4.0 视觉验收

验收范围：1440 × 1024 Windows 桌面窗口，RAGflow 真实仓库，提交演化、因果场、模块影响、风险路径四种模式。基线为 v1.3.0，成品为 v1.4.0 第二轮视觉实现。

## 总结

v1.4.0 通过视觉验收。产品从高饱和、边框密集的“赛博数据 Demo”转为精密工程仪器式的仓库工作台：交互和信息密度没有缩水，模式差异、当前焦点、模块含义与风险依据更容易读取。第二轮曾达到 9.1/10，但经 taste-skill 反套路复审后被退回；最终移除等宽指标卡、多色模式皮肤、过量圆角盒子、模式编号与无用日期，自评分为 9.3/10。

## 01 · 提交演化 — 健康

成品证据：`taste-v140-final-history.png`

- 模式名称是工作区内唯一主标题，工具栏改为仓库与分支上下文，消除了重复标题与装饰编号。
- 原来的无标签色块替换为“模块名 + 主要占比 + 次要模块色段”，列名改为“模块构成”。
- 四张通用指标卡改为开放式刻度列，拓扑、提交信息、模块构成和变更规模仍在一行内完成扫描。

## 02 · 因果场 — 健康

成品证据：`taste-v140-final-causal.png`

- 因果关系与其余模式共用品牌蓝，只用文字和明暗表达路径语义，不再切换整套模式皮肤。
- 上游、当前焦点、下游仍是三段式路径，并保留“只看关联路径”的真实过滤。
- 选择提交只更新焦点和关系，不改变全局 DAG 几何。

## 03 · 模块影响 — 健康

成品证据：`taste-v140-final-modules.png`

- 模块筛选改为无卡片的数据带，把模块名、累计触达量、提交次数和风险放在稳定位置。
- 列头改为“主模块 / 触达”，与卡片筛选后的列表信号相互对应。
- 热点排序、模块筛选和恢复全部模块都通过自动检查。

## 04 · 风险路径 — 健康

成品证据：`taste-v140-final-risk.png`

- 红色只用于高风险信号，低风险与中风险仍同时使用文字等级，避免只靠颜色传达。
- 列表、风险队列和详情面板统一使用同一套 0–100 评分。
- 详情区明确展示变更规模、删除比例、模块跨度、提交结构四个因子，并说明评分范围。

## Taste-skill 设计参数

- Design Read：面向开发者长期使用的高密度本地 Git 桌面工具，采用“精密工程仪器”语言，参考 Primer 的开发者工具秩序，但保留 Git Atlas 的图谱表达。
- `DESIGN_VARIANCE 6`：允许图谱和数据带形成不对称节奏，但不破坏扫描效率。
- `MOTION_INTENSITY 3`：只保留悬停、按下和状态切换反馈，不用持续动画占用资源。
- `VISUAL_DENSITY 9`：数字使用等宽字体，指标以刻度和分隔线组织，不用通用卡片包裹高密度数据。

## UX 与无障碍

- 辅助文字、列头、模式指标与模块构成字号已上调；正文与提交信息保持高对比。
- 交互继续使用 Phosphor 图标与文字标签，不使用难以理解的自绘符号。
- 所有主要按钮、模式标签、列表行和输入框保留 `focus-visible` 状态。
- 风险等级、因果关系和模块信息均有文字，不依赖单一颜色。

## 自动验证

18 项桌面冒烟检查全部通过：搜索、因果模式、选择、稳定拓扑、列表密度、中文 UI、密度控制、活跃度、Codex 跟随、真实仓库加载、分支可达性、关闭跟随后保持仓库、模块构成、父提交对比、模式差异、模块筛选、风险队列、风险解释；渲染器无错误或警告。

## 证据边界

截图能确认层级、裁切、对齐、密度、颜色与主要状态；自动检查覆盖核心交互。屏幕阅读器朗读质量、不同 Windows 缩放比例和超大仓库的长期性能仍需在更多真实设备上持续验证。
